# PCB Copilot — Functional Blocks

## 1. Назначение библиотеки блоков

Библиотека функциональных блоков — инженерная основа проекта PCB Copilot.

Система не должна генерировать схемы «из воздуха». Она должна выбирать и комбинировать заранее описанные и проверенные блоки.

Каждый блок должен иметь:

- код блока;
- название;
- категорию;
- описание;
- условия применения;
- список компонентов;
- типовые предупреждения;
- правила проверки;
- в будущем — KiCad-шаблон.

---

## 2. Список блоков MVP

Первый MVP должен поддерживать следующие блоки:

1. `input_power_24v`
2. `reverse_polarity_protection`
3. `dc_dc_24_to_5`
4. `ldo_5_to_3v3`
5. `stm32_core`
6. `swd_connector`
7. `rs485_interface`
8. `digital_input_24v`
9. `relay_output`
10. `led_indication`
11. `connectors`

---

## 3. Описание блоков

## 3.1. input_power_24v

### Назначение

Входной узел питания 24 В DC для промышленной платы.

### Категория

`power`

### Когда добавлять

Добавлять, если:

- `power.input = "24V DC"`.

### Компоненты

Предварительный список:

- J1 — входной клеммник питания;
- F1 — предохранитель или самовосстанавливающийся предохранитель;
- C1 — входной конденсатор;
- C2 — фильтрующий конденсатор.

### Предупреждения

- Проверить максимальный входной ток.
- Проверить полярность подключения.
- Проверить требования к защите от импульсных помех.
- Проверить температурный режим.

---

## 3.2. reverse_polarity_protection

### Назначение

Защита от переполюсовки входного питания.

### Категория

`protection`

### Когда добавлять

Добавлять, если:

- `power.protection = true`.

### Компоненты

Предварительный список:

- D1 — защитный диод или MOSFET-защита;
- R1 — резистор управления, если используется MOSFET-решение;
- TVS1 — TVS-диод, если требуется защита от импульсов.

### Предупреждения

- Проверить падение напряжения на защитном элементе.
- Проверить рассеиваемую мощность.
- Проверить соответствие максимальному входному напряжению.

---

## 3.3. dc_dc_24_to_5

### Назначение

Преобразователь питания 24 В → 5 В.

### Категория

`power`

### Когда добавлять

Добавлять, если:

- `power.outputs` содержит `5V`.

### Компоненты

Предварительный список:

- U1 — DC/DC converter;
- L1 — дроссель, если требуется;
- D2 — диод, если требуется топологией;
- C3, C4 — входные/выходные конденсаторы;
- R2, R3 — делитель обратной связи, если требуется.

### Предупреждения

- Проверить максимальный выходной ток 5 В.
- Проверить тепловой режим.
- Проверить рекомендации datasheet по разводке.
- Проверить пульсации питания.

---

## 3.4. ldo_5_to_3v3

### Назначение

Стабилизатор питания 5 В → 3,3 В для микроконтроллера и логики.

### Категория

`power`

### Когда добавлять

Добавлять, если:

- `power.outputs` содержит `3.3V`.

### Компоненты

Предварительный список:

- U2 — LDO 3.3 В;
- C5 — входной конденсатор;
- C6 — выходной конденсатор.

### Предупреждения

- Проверить суммарный ток нагрузки 3,3 В.
- Проверить dropout voltage.
- Проверить требования datasheet к ESR выходного конденсатора.

---

## 3.5. stm32_core

### Назначение

Минимальная обвязка микроконтроллера STM32.

### Категория

`mcu`

### Когда добавлять

Добавлять, если:

- `mcu.family = "STM32"`.

### Компоненты

Предварительный список:

- U3 — микроконтроллер STM32;
- C7, C8, C9, C10 — развязочные конденсаторы питания;
- R4 — подтяжка Reset;
- C11 — конденсатор Reset, если требуется;
- Y1 — кварц, если требуется;
- C12, C13 — конденсаторы кварца, если требуется.

### Предупреждения

- Проверить выбранную модель STM32 и количество GPIO.
- Проверить питание 3,3 В.
- Проверить развязочные конденсаторы около выводов питания.
- Проверить цепь Reset.
- Проверить BOOT-пины.
- Проверить доступность SWD для прошивки и отладки.

---

## 3.6. swd_connector

### Назначение

Разъём программирования и отладки STM32 через SWD.

### Категория

`debug`

### Когда добавлять

Добавлять, если:

- `mcu.programming = "SWD"`.

### Компоненты

Предварительный список:

- J2 — SWD-разъём;
- R5, R6 — опциональные последовательные резисторы в линиях SWD;
- TP1, TP2 — тестовые точки, если требуется.

### Предупреждения

- Проверить распиновку SWD.
- Проверить наличие GND и 3,3 В на разъёме.
- Проверить доступность разъёма на плате.

---

## 3.7. rs485_interface

### Назначение

Интерфейс RS-485 для промышленной связи.

### Категория

`interface`

### Когда добавлять

Добавлять, если:

- `interfaces` содержит `RS-485`.

### Компоненты

Предварительный список:

- U4 — RS-485 transceiver;
- R7 — терминальный резистор, если требуется;
- R8, R9 — biasing resistors, если требуется;
- TVS2 — защита линии;
- J3 — разъём RS-485.

### Предупреждения

- Проверить необходимость гальванической развязки.
- Проверить терминальный резистор 120 Ом.
- Проверить защиту линий A/B.
- Проверить направление DE/RE для transceiver.
- Проверить согласование уровней с MCU.

---

## 3.8. digital_input_24v

### Назначение

Дискретный вход 24 В для промышленного сигнала.

### Категория

`input`

### Когда добавлять

Добавлять, если:

- `digitalInputs.count > 0`;
- `digitalInputs.voltage = "24V"`.

Количество экземпляров равно `digitalInputs.count`.

### Компоненты на один вход

Предварительный список:

- R10 — входной ограничительный резистор;
- R11 — подтягивающий/стягивающий резистор;
- D3 — защитный диод или TVS;
- U5 — оптрон или согласующий элемент, если используется развязка;
- C14 — фильтрующий конденсатор, если требуется.

### Предупреждения

- Проверить уровень логического сигнала после согласования.
- Проверить защиту от перенапряжения.
- Проверить входной ток.
- Проверить необходимость гальванической развязки.
- Проверить фильтрацию от дребезга/помех.

---

## 3.9. relay_output

### Назначение

Релейный выход для коммутации внешней нагрузки.

### Категория

`output`

### Когда добавлять

Добавлять, если:

- `relayOutputs.count > 0`.

Количество экземпляров равно `relayOutputs.count`.

### Компоненты на один выход

Предварительный список:

- K1 — реле;
- Q1 — транзисторный ключ;
- R12 — резистор базы/затвора;
- D4 — защитный диод катушки реле;
- J4 — выходной клеммник;
- LED1 — индикация состояния, если требуется.

### Предупреждения

- Проверить ток и напряжение нагрузки.
- Проверить номинал контактов реле.
- Проверить защиту катушки реле.
- Проверить зазоры на плате для коммутируемого напряжения.
- Проверить тепловой режим.

---

## 3.10. led_indication

### Назначение

Светодиодная индикация питания, статуса и связи.

### Категория

`indication`

### Когда добавлять

Добавлять, если:

- `indication` не пустой.

### Компоненты

Предварительный список:

- LED1 — индикатор питания;
- LED2 — индикатор статуса;
- LED3 — индикатор связи;
- R13, R14, R15 — токоограничительные резисторы.

### Предупреждения

- Проверить ток светодиодов.
- Проверить видимость индикации в корпусе.
- Проверить назначение GPIO для status/communication LED.

---

## 3.11. connectors

### Назначение

Разъёмы для питания, входов, выходов и интерфейсов.

### Категория

`connector`

### Когда добавлять

Добавлять всегда.

### Компоненты

Предварительный список:

- J1 — питание;
- J3 — RS-485;
- J4...Jx — входы/выходы;
- J2 — SWD.

### Предупреждения

- Проверить шаг клеммников.
- Проверить токовые параметры разъёмов.
- Проверить механическую доступность.
- Проверить маркировку на плате.

---

## 4. Правила выбора блоков MVP

```text
if power.input == "24V DC":
    add input_power_24v

if power.protection == true:
    add reverse_polarity_protection

if "5V" in power.outputs:
    add dc_dc_24_to_5

if "3.3V" in power.outputs:
    add ldo_5_to_3v3

if mcu.family == "STM32":
    add stm32_core

if mcu.programming == "SWD":
    add swd_connector

if "RS-485" in interfaces:
    add rs485_interface

if digitalInputs.count > 0 and digitalInputs.voltage == "24V":
    add digital_input_24v x digitalInputs.count

if relayOutputs.count > 0:
    add relay_output x relayOutputs.count

if indication is not empty:
    add led_indication

always:
    add connectors
```

---

## 5. Важное правило для разработки

Codex и backend не должны сами выдумывать инженерные решения.

Если блока нет в библиотеке, система должна:

- не генерировать сомнительную схему;
- вывести предупреждение;
- попросить добавить новый блок в библиотеку;
- предложить ручную проверку инженером.

Главный принцип MVP:

> Лучше честно ограничить генерацию, чем создать опасно неправильный проект.
