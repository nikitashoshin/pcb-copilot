# PCB Copilot · Frontend

Интерфейс на Next.js 16, React 19 и TypeScript. Позволяет задать требования к плате, изучить архитектурный черновик и экспортировать результаты работы backend.

[Обзор проекта и полный запуск](../README.md)

## Запуск

Требуются **Node.js 20.9 или новее** и npm. Сначала запустите [backend](../backend/README.md#запуск), затем откройте отдельный терминал в корне репозитория:

```powershell
cd frontend
npm ci
$env:NEXT_PUBLIC_API_BASE_URL = "http://127.0.0.1:5065"
npm run dev -- --hostname 127.0.0.1 --port 3000
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Именно этот origin разрешён текущей CORS-политикой backend.

## Настройка API

Все запросы выполняются через [src/lib/api.ts](src/lib/api.ts).

| Переменная | Значение по умолчанию в коде | Значение для локального запуска |
| --- | --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:5065` | `http://127.0.0.1:5065` |

Задавайте переменную до запуска dev-сервера или сборки и в том же терминале. Вместо переменной текущей сессии можно создать `frontend/.env.local`:

```dotenv
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:5065
```

Файлы `.env.local` исключены из Git. Значения с префиксом `NEXT_PUBLIC_` доступны браузеру и не предназначены для секретов. После изменения адреса перезапустите dev-сервер; для собранного frontend выполните новую сборку.

## Сборка

Из каталога `frontend`, после установки зависимостей:

```powershell
$env:NEXT_PUBLIC_API_BASE_URL = "http://127.0.0.1:5065"
npm run build
npm run start -- --hostname 127.0.0.1 --port 3000
```

Backend должен работать отдельно. Сборка frontend не запускает .NET API.

## Страницы

| Маршрут | Назначение |
| --- | --- |
| `/` | Описание продукта и базовой конфигурации |
| `/new-project` | Форма, текстовый ввод, сводка параметров и запуск генерации |
| `/result` | Обзор результата, риски, уточнения, питание и GPIO, блоки, BoM, проверки и экспорт |

Разделы результата реализованы как вкладки одной страницы. Их переключение использует локальное React-состояние и не создаёт дополнительных маршрутов.

## Пользовательский сценарий

1. Форма создаёт `ProjectSpec`. В текстовом режиме парсер обновляет распознанные поля; остальные значения формы сохраняются.
2. Frontend вызывает `/api/projects/validate` и показывает найденные проблемы.
3. При `isValid: true` отправляется запрос `/api/projects/generate-architecture`.
4. `ArchitectureResult` записывается в `sessionStorage`, затем открывается `/result`.
5. Для CSV, Markdown или ZIP результат передаётся соответствующему endpoint backend.

Текстовый ввод разбирается регулярными выражениями в браузере. Поддерживаются формулировки базового сценария, включая числительные «четыре входа», «два реле» и размеры «80 на 60 мм». Перед генерацией пользователь проверяет полученные значения.

## Проверка и ограничения

- Автоматические тесты пока не добавлены. Основные ручные сценарии собраны в [чек-листе](../docs/manual-test-checklist.md).
- Скрипт `npm run lint` пока содержит устаревший вызов `next lint` и требует обновления для Next.js 16. Команда сборки выше не заменяет линтинг.
- Хранится один результат в сессии вкладки. Постоянное сохранение, история проектов и восстановление формы из результата пока не реализованы.
- Несколько параметров сценария фиксированы: линии 5 В и 3,3 В, защита питания, SWD, уровень входов 24 В, промышленная среда и три индикатора.
- TypeScript-модели поддерживаются вручную; проверки структуры JSON во время выполнения пока нет.

Описание ограничений генерации и планы развития — в [главном README](../README.md#текущие-ограничения).
